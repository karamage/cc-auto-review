PR を、全部自分で読む。

読むのは、あなたが必要な PR だけ。

should注意を向ける先がずれています 採用しました

認証に触れる PR の手前に、小さな PR が 20 件並んでいる。危ない PR の順番は最後になり、疲れた頭で読むことになる。

ほかはアプリがレビューします。残った 3 件を、あなたが読みます。

大量の PR のレビューで疲弊していませんか？Claude Code に PR を先にレビューさせて、危ない PR だけ自分に回すデスクトップアプリを作りました。CC Auto Review は macOS と Linux で動き、diff の横に指摘を並べ、PR ごとにリスクを 0〜100 点で示します。何を投稿するかは、あなたが決めます。

PR を開いてから投稿するまで。

  1. PR を開いた時点で、点数が出ています。

    規模、広がり、影響の大きいパス、危ないコードのパターン、テストの不足を diff だけから数えます。同じ diff なら必ず同じ点になり、PR の説明文で下げることはできません。

  2. Claude が読むのは、変更されたファイルだけです。

    変更ファイルを一時ディレクトリに置くので、clone も API キーの設定も要りません。呼び出し元や型が必要になったら、読み取り専用のヘルパーがこの PR のコミットから取ってきます。

  3. 指摘は、該当する行に付きます。

    blocker と should は、どう起きて何が困るのかを書く決まりです。書けない指摘は question に下がります。

  4. 点数は、根拠とともに動きます。

    Claude は ファイル:行 を示して、点数を最大 ±20 動かせます。裏付けのある重大な問題はエスカレーションになり、最低 60 点まで上がります。計算はサーバーが行います。

  5. 1 件ずつ、採用、却下、編集します。

    この時点では何も投稿されません。指摘について Claude に質問したり、コードを説明させたりして、見つけた問題を下書きに足すこともできます。

  6. あなたのアカウントで投稿します。

    投稿の直前に PR の HEAD を確かめ直し、レビュー後に動いていたら何も投稿しません。投稿先の言語が違えば、投稿の直前に翻訳します。

      よくある質問。

      Claude を MCP で GitHub につなぐのと何が違いますか？

      MCP は、開発中の Claude に GitHub へのアクセスを与えるものです。CC Auto Review はレビューのためのアプリです。あなたのレビュー待ちの PR を一覧にし、Claude の指摘を diff の横に並べて、投稿前に採用・却下・編集できるようにします。PR ごとのリスクも点数で示します。完全自動運転では、レビュー依頼を順に処理し、リスクの高い PR をあなたに回します。また、Claude の GitHub アクセスは既定で読み取りのみで、対象の PR に固定されるので、PR に隠された指示の影響を抑えられます。

      API キーは必要ですか？

      アプリでの設定は要りません。インストール済みの claude をあなたの設定のまま実行し、Claude の認証情報は保存しません。GitHub へのアクセスは gh のログインを使います。

      費用はかかりますか？

      アプリは無料で、MIT ライセンスです。レビューにはあなたの Claude Code のプランか API アカウントを使います。使用量はレビュー画面で確認できます。

      勝手に投稿することはありますか？

      完全自動運転をオンにしない限り、ありません。通常のレビューでは、投稿ボタンを押すまで GitHub には何も届きません。

      リポジトリを clone する必要はありますか？

      ありません。PR の変更ファイルだけを一時ディレクトリに取得します。

      完全自動運転はバックグラウンドで動き続けますか？

      いいえ。アプリのウィンドウを開いている間だけ動きます。

      Windows や Linux で使えますか？

      Linux（x86_64）向けに AppImage と .deb を配布しています。出たばかりで、CI での起動までは確認していますが、実機での確認はまだです。問題があれば Issue で教えてください。WebKitGTK 4.1 が必要です。署名はしていないので、各ファイルと一緒に置く .sha256 で確かめてください。Windows には対応していません。
