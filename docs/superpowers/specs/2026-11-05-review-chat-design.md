# AI レビュー後のチャット 設計

## 目的

AI レビューの後に、レビュー結果への質問、コードの説明の依頼、怪しい箇所の追加の相談をできるようにする。
相談で見つかった問題は、人の判断で投稿する指摘の下書きに追加できる。

## 方式

質問のたびに新しい `claude -p` を実行する。`--resume` は使わない。
セッションは作業ディレクトリに紐づくが、作業ディレクトリはレビューの終了時に消え、起動時の掃除でも消えるため。
会話履歴はクライアントが保持し、毎回プロンプトに含める。

## サーバ

### API

`POST ${PR_PATH}/chat` を追加し、レビューと同じく SSE で返す。
トークン単位の逐次表示はしない。`CommandRunner` が出力をまとめて返すため。15 秒ごとの heartbeat はレビューと同じく送る。

リクエスト:

- `headSha`: 表示中の head。サーバの現在値と異なれば `AppError` で拒否する
- `question`: 質問。必須。上限 4000 文字
- `reference`: 引用箇所。`{ kind: "finding", findingId }`、`{ kind: "line", path, line, side }`、または `null`
- `history`: これまでの発言。`{ role: "user" | "assistant", text }` の配列
- `findings`: 現在の指摘と判定（採用、却下、未判定）。番号はクライアントの表示と揃える
- `model`, `profileId`: レビューと同じ解釈をする

イベント: `snapshot_ready`、`answering`、`answer`（`answer` と `proposals`）、`error`。

### 実行

1. PR のメタ情報と diff を取得し、head SHA を照合する
2. `SnapshotManager` で作業ディレクトリを作る
3. `reviewer/chat.ts` がプロンプトを作り、`claude -p` を実行する
4. 結果を検証し、指摘案を `anchorFindings` で diff に対応づけて返す
5. 成否に関わらず作業ディレクトリを消す

許可するツールはレビューと同じ `allowedTools(remoteReadCommand, profile.allowedTools)`。
環境変数で `remote-read` の読み先を渡す点、PR の設定ファイルを作業ディレクトリに置かない点も変えない。
使用量は `UsageRecorder` に記録する。タイムアウトは `settings.timeoutMinutes`。

### プロンプト

PR の基本情報、説明文、diff の場所、プロファイルの観点、指摘一覧、引用箇所、会話履歴、質問の順に渡す。
説明文、コード、履歴の中の指示には従わせない。区切りタグは既存の `escapeTag` で無害化する。
履歴は合計 16000 文字を上限とし、古いものから削る。回答は画面の言語で書かせる。

指摘案は、ユーザーの相談で問題が裏付けられたときだけ書かせる。

### 結果

Claude は作業ディレクトリの外の JSON ファイルに次の形で書く。

```json
{ "answer": "Markdown の回答", "proposedFindings": [] }
```

`proposedFindings` の各要素はレビューの指摘と同じ形とし、`parse.ts` の検証を再利用する。
`FindingParseError` のときだけ 1 回再実行する。

## クライアント

### 状態

`ReviewSession` に `chat` を追加する。

- `messages`: 発言の配列。AI の発言は指摘案とその追加済みの状態を持つ
- `pending`: 実行中か
- `reference`: 入力欄に付いている引用箇所

既存の保存の仕組みに乗る。`chat` が無い古い保存データは空の会話として復元する。
実行中に再起動した場合は `pending` を解除し、失敗として表示する。

### 画面

- レビュー画面の右に、開閉できるチャット欄を追加する
- 指摘カードと diff の行に「質問」ボタンを置く。押すとチャット欄が開き、入力欄の上に引用箇所が付く
- 回答は改行、インラインコード、コードブロックだけを描く。HTML は差し込まない
- 文言は `messages.ts` の `ja` と `en` に追加する

### 指摘案の追加

AI の発言の指摘案に「指摘に追加」ボタンを付ける。
押すと未判定の項目として下書きに入り、既存の指摘と同じく番号付与、採用、編集、翻訳、投稿の対象になる。
同じ案を二重に追加できないよう、追加済みの状態を発言に持つ。押さなければ下書きは変わらない。

## 利用できる条件

- `phase === "done"` かつ `session.headSha === detail.headSha` のときだけ送信できる
- ずれているときは再レビューを促す案内を出す
- 質問は PR ごとに同時に 1 件。レビューの実行中は送信できない
- 再レビューを始めると会話を消す。指摘番号が変わり、古い会話の参照先がずれるため
- 完全自動運転はチャットを使わない

## エラー

失敗は `{ ja, en }` の文言で該当の質問の下に表示し、再送できるようにする。
質問に失敗しても下書きと会話は失わない。

## テスト

実際の `gh` と `claude` は実行せず、`FakeCommandRunner` を使う。

- `reviewer/chat.test.ts`: プロンプトの内容、タグの無害化、履歴の切り詰め、結果の検証、再実行
- `routes/chat.test.ts`: 入力の検証、head のずれ、作業ディレクトリの後始末、指摘案の対応づけ
- `state/chat.test.ts`: 送信、失敗、下書きへの追加と二重追加の防止、再レビューでの消去、古いデータの復元

## 対象外

- 回答の逐次表示
- 実行中の質問のキャンセル
- 既存の指摘を AI が書き換える提案
- レビュー前のチャット
