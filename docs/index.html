CC Auto Review is a desktop app for macOS and Linux that reviews GitHub pull requests with the Claude Code you already have. Findings sit beside the diff, every PR gets a risk score from 0 to 100, and you decide what gets posted.

Score a real PR in your browser, no install.

One pull request, from open to posted.

  1. Open the PR. It already has a score.

    Size, spread, sensitive paths, risky patterns and test gaps are counted from the diff alone. The same diff always gets the same number, and nothing written in the PR description can lower it.

  2. Claude reads only what changed.

    The changed files go into a temporary directory. There is no clone and no API key to set up. When Claude needs a caller or a type from elsewhere, a read-only helper fetches it from this PR's commits.

  3. Findings land on the lines they are about.

    A blocker or should has to state how the problem happens and what goes wrong. If it can't, it is downgraded to a question.

  4. The score moves, with citations.

    Claude can move the score by up to 20 points either way, citing file:line. A verified serious problem is an escalation, which raises it to at least 60. The server does the arithmetic.

  5. You accept, reject or edit each one.

    Nothing is posted yet. Ask Claude about a finding, or have it explain the code, and add what you find together to the draft.

  6. Post it from your own account.

    The PR head is checked again first. If it moved since the review, nothing is posted. Findings are translated right before posting when you post in another language.

      What comes back to you

      • Paths you list: CI, migrations, infra, secrets, auth, billing and crypto by default. These skip the AI entirely.
      • More than 1,000 changed lines. Lock files and dist/ don't count.
      • A risk score above 50, or any escalation.
      • Anything matching criteria you write in plain language, such as “breaking API changes”.
      • Still unresolved after 3 comment rounds.

      Autopilot runs only while the app is open. Reviews it posts come from your GitHub account and say they are automated. It runs Claude Code automatically, so check Anthropic's terms before turning it on, or use an API key.

      A pull request can't change the rules it's reviewed by.

      Text in a PR can be written to steer a reviewer, so every review runs inside a short list of permissions.

      What Claude can do

      • +readthe PR's changed files and diff, in a temporary directory
      • +readCLAUDE.md, AGENTS.md and REVIEW.md, from the base branch
      • +fetchother files through remote-read: GET only, pinned to this PR's repository and commits
      • +writeone result file

      What it can't

      • −readanything else on your Mac
      • −rungit, arbitrary gh commands, other shell commands
      • −load.claude/, .mcp.json and CLAUDE.local.md from the PR
      • −sendusage data. The app has no telemetry

      What this doesn't cover

      Allow rules in your own Claude Code settings and a profile's extra tools still apply, so keep them narrow. PR text can still try to influence the review itself, so read what the app posts.

      Where your code goes

      The app talks to GitHub through gh and to Claude through claude, as you have them configured. Its server listens on 127.0.0.1 and only accepts requests carrying a token made at launch.

      The rest of what it does.

      • +

        Set perspectives, team guidelines, things not to report and a finding limit. Ships with Standard, Security focused and Quick. Preview shows exactly what Claude receives.

      • +

        Prior review comments are marked fixed, unfixed or unverified against the current code. An author saying “fixed it” doesn't count as evidence.

      • +

        Your CLAUDE.md, AGENTS.md and REVIEW.md are read, always from the base branch.

      • +

        When the author pushes or replies, the review runs again. Nothing is re-posted without you.

      • +

        Use a different profile by repository, label or mention, such as @org/security.

      Questions.

      How is this different from connecting Claude to GitHub through MCP?

      MCP gives Claude access to GitHub while you build. CC Auto Review is for the review side: it lists the PRs waiting on you, shows Claude's findings beside the diff to accept, reject or edit before posting, and scores each PR's risk. The autopilot can work through your review requests and hand the risky ones to you. By default, Claude runs with read-only GitHub access pinned to that PR, so instructions hidden in a PR have less to work with.

      Do I need an API key?

      No setup in the app. It runs your installed claude as you have configured it and stores no Claude credentials. GitHub access goes through your gh login.

      What does it cost?

      The app is free and MIT licensed. Reviews use your Claude Code plan or API account, and the review screen shows your usage.

      Does it post anything without asking?

      Not unless you turn on the autopilot. In a normal review, nothing reaches GitHub until you press post.

      Do I need to clone my repositories?

      No. Only the PR's changed files are fetched, into a temporary directory.

      Does the autopilot keep running in the background?

      No. It runs only while the app window is open.

      Can I use it on Windows or Linux?

      Linux x86_64 is available as an AppImage and a .deb. These builds are new: they start in CI but have not been tested on a real desktop yet, so please report any problems. They need WebKitGTK 4.1 and are not signed, so check them against the .sha256 file next to each download. Windows is not supported.
